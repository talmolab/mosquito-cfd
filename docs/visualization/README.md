# Visualization tooling — synthetic reference figures

**These two PNGs are generated from synthetic test fixtures, not real corpus data.**

- `coarse_vs_fine_comparison.png` — generated by
  `mosquito_cfd.force_surrogate.comparison_figure.build_coarse_vs_fine_comparison` from
  `fixtures/coarse_predictions.parquet` / `fixtures/fine_predictions.parquet`, the exact
  fixture used by `tests/test_comparison_figure.py::test_coarse_vs_fine_panel_means_match_groupby`.
- `diagnostic_config_mean_collapse.png` — generated by
  `build_config_mean_collapse_diagnostic` from `fixtures/diagnostic_{coarse,fine}_predictions.parquet`
  and `fixtures/{coarse,fine}_metrics.json`, the exact fixture used by
  `tests/test_comparison_figure.py::test_config_mean_collapse_diagnostic_matches_metrics_json`.
  The two "per-config mean" panels look identical by design — the fixture varies the
  `config_resolved.CF_x.config_mean_r2` value between the coarse (`0.944`) and fine (`-31.95`)
  `metrics.json` files, not the plotted predictions. That R² collapse is only visible in
  `diagnostic_config_mean_collapse_metrics.json`, not in the PNG itself — the same
  "waveform fit looks fine, R² has collapsed" gap this diagnostic exists to catch.

Each PNG's `*_metrics.json`/`*_run_metadata.json` siblings are real outputs of the CC-1
run-metadata sidecar mechanism (git commit, hardware, timestamp) exercised against the synthetic
inputs above — they are not evidence of any real simulation or CFD run. `docker_image` is a
placeholder digest (`sha256:` + repeated `a`). Each `*_run_metadata.json` also carries a
top-level `"synthetic": true` marker (added after generation, since
`capture_surrogate_run_metadata`'s `extra` fields are internal to library callers, not
CLI-exposed) so the disclosure travels with the JSON itself, not only this README — the real
git commit/hostname/GPU alongside a placeholder digest could otherwise be mistaken for a real
captured run by anyone reading just the sidecar.

`fixtures/` holds the tiny synthetic parquet/JSON inputs so the PNGs and `*_metrics.json`
outputs are regenerable byte-for-byte without reading test source. The `*_run_metadata.json`
sidecars will **not** come back byte-identical from the commands below — `run_id` is a fresh
random UUID each call, `git.commit` reflects whatever commit you run from, and the `synthetic`
marker above is a manual post-processing step this repo's generation script applies, not
something the CLI itself writes.

```bash
uv run python scripts/make_comparison_figure.py \
    --coarse-predictions docs/visualization/fixtures/coarse_predictions.parquet \
    --fine-predictions docs/visualization/fixtures/fine_predictions.parquet \
    --out-dir docs/visualization \
    --docker-digest "ghcr.io/talmolab/mosquito-cfd@sha256:$(printf 'a%.0s' {1..64})" \
    --timestamp 2020-01-01T00:00:00+00:00

uv run python scripts/make_config_mean_collapse_diagnostic.py \
    --coarse-predictions docs/visualization/fixtures/diagnostic_coarse_predictions.parquet \
    --fine-predictions docs/visualization/fixtures/diagnostic_fine_predictions.parquet \
    --coarse-metrics docs/visualization/fixtures/coarse_metrics.json \
    --fine-metrics docs/visualization/fixtures/fine_metrics.json \
    --out-dir docs/visualization \
    --docker-digest "ghcr.io/talmolab/mosquito-cfd@sha256:$(printf 'a%.0s' {1..64})" \
    --timestamp 2020-01-01T00:00:00+00:00
```
