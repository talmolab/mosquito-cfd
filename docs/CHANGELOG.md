  - `docs/coordinate-convention.md` gains a `## Force and moment sign` section. It states that IAMReX's `ib_force`/`ib_moment` act on the fluid and that derived wing coefficients are to be the IB force and moment on the wing. Pinned pending notes record that the committed corpus coefficients and flapping-wing series still carry the on-fluid sign; a guard ties each note to its data or code path.
  - `tests/test_ib_force_sign_convention.py` pins the convention by physics. Over all 57 committed runs, the work the solver's hinge-referenced moments do from rest is non-negative at every row and in its increment after the impulsive-start transient (`t = 0.005`), and raw force and moment share one convention. The coefficient-side mirror is a strict xfail until the corpora are re-extracted.
  - New helpers: `wing_kinematics.angular_velocity` (the lab-frame `Ω` of `R = Rz(φ)·Ry(α)·Rx(θ)`), and `force_surrogate.force_on_wing` and `IB_FORCE_ACTS_ON`, which nothing calls yet.
  - `ForceCoefficients`/`MomentCoefficients` are documented as sign-agnostic, and `cf_z` as the lab vertical rather than "span-normal".
  - The force-CSV name `IB_Particle_1.csv` is recorded as verified against the A40 corpus (#19).

Per step rather than per wingbeat: the speedup divides by the cost per row, each row is one timestep, and a wingbeat takes `1/(f*·dt)` steps, so per-wingbeat time scales with the frequency by construction. The fine README states the per-step range over the 27 runs alongside the median (#110)

The coarse surrogate was retrained at seeds 1234–1238: `surrogate.pt` and `holdout_predictions.parquet` came out byte-identical to the committed ones and every seed's config-resolved R² matched `seed_variation.json` exactly, so only `metrics.json` and `run_metadata.json` (now `seeds.sweep`) changed (#127, #125)
- Stage-2 field-surrogate reader `src/mosquito_cfd/field_surrogate/`: `read_field_snapshot` returns an immutable `FieldSnapshot` (dense FP64 arrays in code units, cell-center coords, `dx`, the plotfile's physical `time`, plus `source`/`max_level` provenance) with a C-ordered `PointCloud` view whose `cell_volume` column exists so the still-open CC-F3 AMR decision lands additively; `FieldCorpus` addresses plotfiles by `(config_id, step)` against a caller-supplied root, discovering steps from the `plt*` directories actually on disk rather than a deck's `plot_int`; `to_domino_volume` emits DoMINO's five volume-half keys with no batch dimension. The eight geometry-half keys (`geometry_coordinates`, `sdf_*`, `surface_mesh_*`) are absent rather than zero-filled and are F3's work — stock DoMINO is a geometry→fields surrogate, so `volume_fields` is a training target, not an encoder input (verified against `NVIDIA/physicsnemo` `main` + the 26.05 docs), and this corpus's plotfiles carry no pressure field, only its gradient (IAMReX's component list is deck-dependent, so this is a claim about our decks, not the solver; a real wing plotfile's Header was inspected directly). Multi-level plotfiles are refused with the open CC-F3 decision named. Region selection matches the legacy `extract_eulerian_box` whenever the request meets the domain on every axis (`lo <= domain_right_edge`, `hi > domain_left_edge`). Outside that it deliberately differs: `halo` pads the request first and only in-domain cells within that reach are returned. The legacy adapter instead returns edge cells for a request arbitrarily far outside, including a spurious cell at index 0 for a request wholly below the domain at `halo = 0` (#105)

Committed-artifact guards now run over both corpora (#110)
- **BREAKING:** the force-surrogate evidence figure reports skill over the phase-only baseline instead of config-resolved R²: each panel shows the plotted seed's skill with its 5-seed range, pointwise R² and RMSE, and the caption defines skill, gives the baseline's pointwise R², states the skill floor across seeds and discloses the off-panel `CF_mx`/`CF_mz` skill. `evidence_figure_metrics.json` drops `config_mean_r2` and adds `primary_seed`, `n_seeds`, `skill` (committed/min/max for all six targets), `pointwise_r2`, `phase_baseline_pointwise_r2` and `skill_floor` (#116). `make_evidence_figure.py` loses `--seed`; the provenance seeds are read from `metrics.json`'s `seed_sweep`. Config-resolved R² stays in `metrics.json` and the README, which now explains why it left the figure; the README's guarded skill table is the one copy of the values (#127)
- **BREAKING:** moment coefficients `CF_mx/CF_my/CF_mz` are now taken about the deck's declared hinge (`particle_inputs.hinge_*`) instead of the IB particle's own origin. Extraction applies the parallel-axis shift `M + (r_origin − r_hinge) × F` before normalizing, deriving `r_origin` from the CSV's `X,Y,Z` and `r_hinge` from each config's deck, which is located through the manifest's `input_file` and checked against its run's `deck_sha256` when one was recorded.
  - `build_dataset` now returns `DatasetBuild(frame, dropped, provenance)` rather than `(frame, dropped)`.
  - Both committed `dataset.parquet` files were re-extracted. Only `CF_mx`/`CF_mz` changed; raw `Fx..Mz`, the force coefficients and `CF_my` are unchanged.
  - Each corpus's `run_metadata.json` now records `moment_reference` (per-config origin, hinge, offset and deck hash) and `extraction_inputs` (the runs directory and a sha256 per consumed CSV).
  - The coarse `surrogate/` is retrained on the hinge-referenced targets (seed 1234, protocol unchanged), and the evidence figure and README are regenerated from it. Retraining was observed to be bitwise-reproducible at a fixed seed on the training host, so old and new are compared as 5-seed ranges (seeds 1234–1238, in `surrogate/seed_variation.json` and the README's honest-reading table) rather than against a noise floor. Under a pre-registered, conservative rule (a target moved only if its two ranges are disjoint), no shift was detected, though five seeds a side cannot rule out shifts as large as the seed spread. `CF_mx` stays seed-robust; `CF_x`, `CF_my` and `CF_mz` swing widely with the seed at six holdout configurations, and the committed seed-1234 model is a low draw for `CF_x`, `CF_y` and `CF_mz`. The caption now names its seed, and the README quotes ranges rather than single-seed rankings. The surrogate's `run_metadata.json` records the training dataset's sha256, and the coarse `sweep_provenance.json` credits this change instead of the #71 cluster run (#118, #126)
- `docs/field_surrogate/roadmap.md`: Stage-2 F3 reframed from "DoMINO encoder: field snapshot → latent z" — which describes no DoMINO configuration, since stock DoMINO is geometry→fields (verified against `NVIDIA/physicsnemo` `domino/model.py` @ `cbb1bf1`) — to a three-arm bake-off (`add-field-surrogate-bakeoff`): a windowed-kinematics MLP first, a hover-only gate against the corpus's measured CFD uncertainty that can skip the field models on hover data but never cancels new runs, then PhysicsNeMo `Mesh_Reduced` + `Sequence_Model` and DoMINO used as designed. Records the error's provenance, adds ~3–5 commanded-change configs (kinematics switching mid-run) that always run, after arm A, declines a pressure-only regeneration (IAMReX pressure is nodal; new decks set `amr.derive_plot_vars = avg_pressure`), resolves open question #1, re-scopes F4/F5, and removes the dangling `CC-F5` references (#123)
- `benchmarks.stress_integral.extract_eulerian_box` now delegates to `field_surrogate.snapshot.read_field_snapshot`, leaving one Eulerian-box covering-grid read path (CC-F2); it stays every in-repo caller's entry point (CC-F1). Import path, signature, returned keys, value types and array writeability are unchanged. Deliberate narrowings: a NaN or non-3-vector `lo`/`hi` (the error names `(-inf,)*3` for full extent), a `halo` that is negative or not of an integer type (bool, and integral floats such as `2.0` included), and an fp32 on-disk plotfile (previously accepted silently as upcast float64) now raise `ValueError`, as does a plotfile whose precision yt can no longer report (its private `ds.index._dtype`); the region follows the reader's "halo is reach" rule (see the #105 entry), identical to before wherever the request meets the domain on every axis and never more cells elsewhere: a request that misses the domain on some axis now returns only the in-domain cells within `halo` reach, where it previously returned `halo` edge cells, or one spurious cell at index 0 for a request wholly below the domain at `halo = 0`. ### Fixed
- Argo `activeDeadlineSeconds` (86400s → 98280s, both sweep and smoke workflows), `retryStrategy.retryPolicy` (`"OnFailure"` → `"Always"`, so a pod deleted by preemption is retried), and `backoff.maxDuration` (`"4h"` → `"20h"`, actually covering the configured retry limit); `submit_workflow.sh smoke` now defaults to the corpus's CFL-worst config rather than its mildest one, and rejects `--parallelism`/`--active-deadline-seconds` (issues #95, #90) (#97)
- `kinematics_video._span_tip_index` picked the wing-root marker instead of the true wingtip whenever a `.vertex` file's max-span markers are exactly tied on both sides of the wing (true for the committed `wing.vertex`) and the hinge/center don't coincide in `y` (true for `examples/prelim_sweep_fine`'s convention) — `np.argmin`'s first-occurrence tie-break had no hinge awareness, silently picking the root side and corrupting `span_arm`/`chord_axis_extent` in `*_kinematics_preview_metrics.json` and the video's own tracked-tip overlay. Now selects the tied candidate farthest from the hinge (#87, #89)
- `flow_video.build_flow_video`'s `lev-3d` mode (the Q-criterion vortex isosurface video) never showed the vortex — the isosurface data was correct, but the wing overlay's fixed `computed_zorder=False` (correct for the thin-plane `combined-3d`/`zvelocity-3d` modes) made the opaque wing fully occlude the mesh every frame, silently. `lev-3d` now falls back to mplot3d's default per-artist depth sort and renders the mesh translucent (`DEFAULT_LEV_MESH_ALPHA=0.65`, matching the original proven vault rendering), exposed as a new `--lev-mesh-alpha` CLI flag on `make_flow_video.py` (#88, #89)
- `compute_wall_time_s()` (`src/mosquito_cfd/force_surrogate/metadata_capture.py`) picked the single globally-latest-finishing Argo status node across an entire workflow's `status.nodes`, so a multi-config fan-out sweep (several configs sharing one Argo workflow) gave every config the same wrong `timing.wall_time_s` — whichever config's pod happened to finish last. Adds an optional `pod_name` parameter threaded through `compute_wall_time_s`/`resolve_wall_time_s`, auto-derived by `assemble_run_metadata` from the pod's own already-recorded `orchestration.pod`, that selects the matching node directly instead of the unfiltered global maximum, raising `ValueError` (rather than silently falling back) if the pod name has no matching node or the matched node isn't itself a valid candidate (#65)
- `extract_git_info()` (`src/mosquito_cfd/force_surrogate/metadata_capture.py`) hard-failed with no override whenever a pod-side `run_metadata.json`'s `git` block had no valid `commit` — unconditionally true for every `:fp64` run, since the image's `COPY` list never includes `.git`. Adds a `--git-commit` CLI override (`scripts/generate_run_metadata.py`, via a new `resolve_git_info()`) for already-collected metadata, plus a build-time-baked `MOSQUITO_CFD_COMMIT` Docker ARG/ENV/LABEL (`docker/Dockerfile.fp64`, `.github/workflows/docker.yml`) that `get_git_info()` (`src/mosquito_cfd/benchmarks/metadata.py`) now falls back to automatically for every future CI-built image, after its existing WSL-worktree retry has failed (#66)
- `get_git_info()` (`src/mosquito_cfd/benchmarks/metadata.py`) now resolves Windows-created git worktrees read via WSL — previously it silently dropped git provenance (`git.commit`, `git.branch`, `git.dirty`, etc.), reporting the same "not a git repository" error used for a genuinely missing repo. Adds a reactive retry: on the first failure, if `.git` is a worktree pointer file naming a Windows drive-letter gitdir (e.g. `C:/...`), translate it to its WSL mount equivalent (`/mnt/c/...`) and retry once with `GIT_DIR`/`GIT_WORK_TREE` set; the non-worktree path is unchanged (#77)
