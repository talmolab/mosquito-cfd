- Every way a force-surrogate JSON file can fail to load is a labelled `ValueError` (`harden-json-loader`).
  - New stdlib-only `mosquito_cfd/_json_loader.py` holds `load_json_clear_error(path, *, label, require_object=True)`. Bytes that are not UTF-8, anything `json.loads` refuses (including nesting beyond the recursion limit and an integer beyond Python's digit limit) and, by default, a top level that is not a JSON object are each exactly a `ValueError` naming the label and path. The malformed-JSON message is unchanged. Errors opening the path are not wrapped. `force_surrogate.sidecar.load_json_clear_error` is a re-export of the same object.
  - Callers: the acceptance gate's provenance reads, `corpus_guards`, and `load_pod_run_metadata` use the object check. The gate and `source_config_fields` read the manifest through `load_manifest_configs`. `read_units_sidecar` loads through the shared loader. `dataset`'s per-config run_metadata read opts out and keeps its `ConfigExtractionError`s and their messages.
  - `mosquito_cfd/_manifest.py` loads through `_json_loader`, so its contract is now "the standard library and the stdlib-only `mosquito_cfd._json_loader`". `_provenance.read_run_metadata` keeps its own loader; a drift test sends the same inputs through all three.
  - **BREAKING (minor):** `source_config_fields` raises `ValueError` for anything the shared manifest reader rejects. A defect in any config of the manifest now counts. Before, only the requested config was looked at: a config missing a required key was a `KeyError` (only if this function read that key), a manifest with no `configs` key a `KeyError` "… not found (available: [])", a non-list `configs` a `TypeError`, a non-mapping config an `AttributeError`, and a duplicate config name was accepted. An absent config and a missing `max_step` are still `KeyError`. Every config of every committed manifest still passes.
  - **BREAKING (minor):** through `load_json_clear_error`'s callers (the gate, `record_check_result`, `corpus_guards`, `load_pod_run_metadata`), deep nesting and a non-object top level raise `ValueError` instead of `RecursionError`, `AttributeError` or `TypeError`, and non-UTF-8 bytes raise exactly `ValueError` (chained from it) instead of a bare `UnicodeDecodeError`, so `except UnicodeDecodeError` no longer catches it. `load_json_clear_error` itself now rejects a non-object top level unless called with `require_object=False`.
